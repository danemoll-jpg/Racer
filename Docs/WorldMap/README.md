# Actual-geometry world cartography

Open [WORLD_MAP.png](WORLD_MAP.png) for the planning atlas, or [WORLD_BASE.png](WORLD_BASE.png) for clean geography. The documentation image is **10,700 × 6,680** including margins; its map area is **10,400 × 6,240**, covering **X −1350…1650, Z −850…950**. North is Unity +Z. A light 200 m grid and labeled X/Z margins support editing coordinates without obscuring geography. Dark outside areas mean no authored ground there, not undiscovered terrain.

## Source and scene variants

These are orthographic Unity renders of actual saved meshes, materials, trees, roads, buildings, water and terrain. No geography is hand-drawn or generated by an image model. Camera orientation is `LookRotation(Vector3.down, Vector3.forward)`; world X increases right and Z increases up. Temporary cameras, fog/LOD adjustments and hidden vehicle/checkpoint renderers are never saved into a scene.

**There is no single scene containing every regional course revision.** The forest scene contains the lake/Forest trail, Backyard contains its newer dump/ravine/trail, and Mountain has the farther eastern terrain. Therefore the master is an explicitly registered **scene composite**, not a claim that every regional feature coexists in every playable scene:

- Mountain Forward supplies the full 3000 × 1800 m foundation, including the eastern extension.
- Forest Forward supplies X −1350…800 across the same Z extent, including the actual lake and forest trails.
- Backyard Reverse supplies the latest property/crossing geography and replaces X −40…600, Z −220…206.666667, the same exact documented Backyard cartography window used previously.
- Replacement is a world-coordinate crop/resample of actual rendered pixels, with no manually drawn roads, terrain or water. For precise course-specific edits, use that scene's image/JSON. Regional source renders remain alongside the master.

The **full menu map uses one shared permanent world base** (`Assets/Resources/WorldMaps/PermanentWorld.asset`) in 0.46.0. It combines the registered regional renders above with muted paved-road and dirt/trail/shortcut traces exported from all eight existing scenes. It is independent of the selected race. The optional teal/gold active-course overlay remains separate. No scene/course/save IDs or physical routes are changed to produce this map; the regional scene differences described above still exist in gameplay. The map is a world-network overview, not a promise that every revision of a shared regional mesh coexists in a single playable scene.

The shared image is 5200 × 3120, X -1350…1650 / Z -850…950. Paved roads are pale grey; permanent dirt trails/shortcuts are muted tan. The network includes Laurel's existing path, McFadden Cut, Tree-Top Trail and Abandoned Cabin Jump regardless of current course. There are no hidden-collectible or undiscovered-landmark labels baked into the menu base. Existing visited-cell dimming and discovered-marker rules remain in force; no discovery/save state is granted by loading the map. The eight scene images/JSON remain available as precise scene-specific references.

Correct property labels are Moll's, Roger's, McFadden's and Anderson's. See [cleanup validation](../WorldCleanup/VALIDATION.md), [preserved Backyard anchors](../WorldCleanup/REFERENCE_ANCHORS.md), and [Western Gullies audit](../WorldCleanup/WESTERN_GULLIES.md). ## Course overlays and coordinates

`Overlays/<scene>.png` provides a separately selectable transparent course layer aligned to the master `WORLD_BASE.png`. Each uses exported actual road points, shortcut points and gates: teal main route, gold shortcuts, travel arrows, blue checkpoints and white start/finish. Forward/Reverse comes from the actual corresponding scene, never from reversing an invented line. Do not stack every course over the normal map.

Per-scene JSON files contain exact image bounds, route/branch/gate coordinates and existing destination anchors. For a north-up image of width W and height H:

`pixelX = (X - xmin) / worldWidth * W`

`pixelY = (zmax - Z) / worldHeight * H`

Unity UI UVs instead increase upward: `u=(X-xmin)/width`, `v=(Z-zmin)/height`. Player, destination, waypoint and course overlays use the same conversion as their background image.

The full menu map retains player heading, discovered landmarks/collection markers, waypoint placement/clearing, destination selection and confirmed free-roam travel, mouse/controller pan/zoom and return-to-game behavior. Unexplored geography is dimmed; discovery IDs and the existing `woodstock-world-v2` save grid are unchanged. **Show / hide course** toggles the current actual course without permanently cluttering the map. Development coordinates appear only in documentation.

**RacingMiniMap.cs and all scene minimap settings are unchanged.** None of the world-map code drives the small racing minimap.

## Regeneration

Use the existing connected Unity Editor in saved, compiled Edit Mode. First follow CODEX_RULES.md and preserve a safety checkpoint. Commands run from the Racer root:

1. `unity command run_script --caller plugin --skill unity-cli --file Tools/Capture-CleanupWorldMaps.cs --result-only` generates seven per-scene reference images/assets, exact geometry JSON, all three regional master source PNGs, and verifies added-tree grounding. Wait for `capture-done.txt`; inspect `capture-error.txt` if present. Each saved scene is loaded and the original restored, with no scene saves.
2. Optional individual master regeneration (already covered by step 1): `unity command eval_file --caller plugin --skill unity-cli --file Tools/Capture-WorldExtension.cs --result-only` generates `MOUNTAIN_BASE.png`; wait for `extension-done.txt`.
3. Optional individual master regeneration (already covered by step 1): `unity command eval_file --caller plugin --skill unity-cli --file Tools/Capture-WorldForest.cs --result-only` generates `FOREST_BASE.png`; wait for `forest-done.txt`.
4. Run `Tools/Render-WorldMap.py` with the bundled Python/Pillow runtime. It rebuilds the coordinate master, preview and independent course overlays. Then run `Tools/Render-PermanentNetwork.py`, followed by `Tools/Import-PermanentNetwork.cs` through `run_script`, to regenerate/import the shared menu image and permanent network. The exported route inventory in `Docs/WorldCleanup/audit.json` is valid for this geometry-preserving cleanup; refresh it deliberately when physical routes change.
5. For the Backyard planning sheet, run the existing `Tools/Capture-ShortcutTrackMap.cs` through `eval_file`, then `Tools/Render-ShortcutTrackMap.py`. It uses the same camera orientation and actual-scene source method.
6. Inspect full-map UI alignment and document actual results. Capturing/regenerating maps must not save scene changes. Material future world changes should regenerate affected scene assets and the master sources. If world extents grow beyond the documented source crops, update the capture bounds/composite regions deliberately using the measured mesh bounds; never stretch an old map over new geography.

Capture operations are asynchronous; do not treat a CLI timeout as permission to launch duplicate work. Completion/error files and the Editor log are the evidence. Remove stale completion/error markers before a regeneration so they cannot be mistaken for a new run.

## Tree-Top correction and finish flow

The original vegetation authoring sampled candidate plants at Y=0 with `RaceRoad.Project`, which measures 3D distance. That failed to exclude plants on the elevated main trail. `Tools/Fix-TreeBrushClearance.cs` measures the **entire actual plant mesh in X/Z**, removing only complete Tree-Top clusters intruding within 4.25 m of the main centerline. It retained 538 of 621 plants; nearest remaining foliage is 4.294 m from center, at least 1.644 m beyond the nominal 2.65 m half-width. Scene transforms, terrain, platforms, collision, route points and the resistance component are unchanged.

The post-finish button now explicitly says **Press Space to Complete Race**, or the resolved connected controller submit button plus Space. Its existing guard, click handler and CR-064 estimator are unchanged: only after human finish, only while unfinished AI remain, measured finishes retained, only remaining AI estimated, normal final results opened. See [validation](VALIDATION.md).
